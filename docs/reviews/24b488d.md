## Release blockers (do these, in this order)

### R1 — Conversation must be reachable (Inbox)
The phone bar drops Inbox, so rooms are reachable only from a post. Conversation is step 3 of the core loop; a reply someone can't find breaks the loop.
- Add an **Inbox icon with an unread badge** in the header of every talent screen, on phone and desktop, linking to `/rooms`.
- Use the existing unread/notification data. If no unread count exists, show the icon without a badge; **don't invent one**.

### R2 — Work must be "what I'm in", not just applications
`WorkScreen` lists applications only. Union the endpoints that already exist, **client-side, with no new table**:
- `GET /applications`
- `GET /marketplace/my-bids`
- interviews via the existing `/mine` endpoint
- posts I host (my ACTIVITY/ASK posts)
- activities I joined

If there's no "posts I joined" read endpoint, add one **additive, read-only** endpoint (for example `GET /posts/joined`) with an ownership test.

Each row shows: kind, status, and **one next step** (open room, see bids, prepare interview, mark attendance, close need). Group rows as **Active** or **Done**.

### R3 — Close the loop: OUTCOME → IDENTITY
The golden path needs "outcome recorded → shows on profile". The backend already has `PUT /posts/{id}/status` and `PUT /posts/{id}/joins/{joinId}/outcome`.
- The owner of an ASK can **mark it resolved**. This sets status to `CLOSED`, with a confirm sheet.
- The host of a past ACTIVITY is prompted in Work to **mark attendance** (the existing outcome endpoint).
- **Profile** shows real, verifiable counts only:
  - needs resolved,
  - activities hosted,
  - activities joined,
  - projects won.

  **No reputation score and no "reliability" from attendance.** Attendance isn't reputation until there's a confirmation/dispute policy (protocol §4).

### R4 — "Offer" must not be saved as an UPDATE
Create → "I can offer" currently posts `intent: update`, so offers show up as updates.
- Add `OFFER` to `PostIntentType` (additive), plus a migration if a DB check constraint exists.
- Accept `offer` in feed, search and create, and label it "Offer" on cards.
- Keep Jenny's `arena.createPost` body contract test green. Extend it if the intent set is validated there.

### R5 — Remove the fake Pulse
`FeedScreen.tsx:17` renders `{data.length} things in this feed`. That's the page size, so it will nearly always read 20. It's accurate but meaningless, and reads like network activity.
- **Remove it for v1.**
- A real Pulse later needs a server count (for example, new needs/activities in the last 24h within the user's area). That's a backlog item, not a v1 task.

### R6 — Performance budget
First JS on `/home` is still over 200KB gzipped. It's a mission budget; meet it (lazy-load the command palette, GSAP, maps and 3D; audit shared chunks). Don't loosen the assertion.

### R7 — Finish STEP 6 on the preview
- All routes × all roles.
- The 12-step mobile golden path, now including R3's outcome step.
- The enterprise path: post → review → interview → hire.
- IDOR tests on every write, including any new endpoint from R2/R4.
- Visual QA at 390×844, 412×915 and 1440×900 (protocol §8): logged out, talent and company, plus the empty, error and offline states.

### R8 — Finish the landing page rewrite
It must say: a network for needs, people, activities and work nearby, with Jenny helping. Only real counts, no job-board copy.
